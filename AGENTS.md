# Grub (grub.cam) — agent notes

Cambridge college and University menus, hours and access, live. Vite + React 19 + TypeScript + Tailwind 4 SPA reading Supabase (Postgres). **The database is the system of record**: sites, venues, hours and menus live there, not in the repo. A site is a college or a University site (West Cambridge, Sidgwick, a museum, …); a venue belongs to one. The repo holds code, migrations, and how each venue publishes its menu.

## Commands

| Command | What |
|---|---|
| `npm run dev` | Vite dev server (needs `VITE_SUPABASE_*` in `.env`) |
| `npm run ingest -- [--only jesus,homerton] [--dry]` | Copy every source's channel to `venues`, then fetch every scripted source from this week's Monday until a week comes back empty → Supabase |
| `npm run ingest:manual -- menu.txt [...] [--dry]` | Save hand-transcribed menus → Supabase (format at the top of `scripts/ingest/manual.ts`) |
| `npm run ingest:prices -- prices.txt [...] [--dry]` | Save a venue's posted price list → Supabase, replacing the last one (format at the top of `scripts/ingest/prices.ts`) |
| `npm test` | Vitest (time logic, filters, search against a real-data snapshot, SEO output, adapters against saved pages) |
| `npm run search:snapshot` | Save what the app loads today to `src/lib/fixtures/snapshot.json` for the search tests (then re-check their dish examples) |
| `npm run typecheck` / `npm run lint` | `tsc -b` + scripts tsconfig / oxlint |
| `npm run build` | typecheck + Vite build + `scripts/prerender.ts` → `dist/` (needs `VITE_SUPABASE_*`: pages are rendered from live data) |

`--dry` fetches and validates without writing. If ingest gets "fetch failed" for Magdalene locally, run with `NODE_USE_SYSTEM_CA=0` (keychain cross-signed certs break that chain).

## Layout

- `scripts/ingest/sources.ts` — **how each venue publishes its menu**: one entry per venue (`venues.id` = `<site>/<venue>`), channel (html/json/pdf/sway/canva/app/email/intranet/none), URL, cadence, notes, and an `adapter` for the 14 scripted ones (`scripts/ingest/sources/*.ts`: 11 colleges, plus `ucs.ts` for the three University Catering pages with a weekly menu). Adapters must take dates from the source, never from the requested week; tests run them on saved pages in `sources/fixtures/`. Each run copies channel, URL and scripted-or-not to `venues.menu_channel/menu_url/menu_scripted` (`0007`), for `/coverage`; edit them in `sources.ts`, not the dashboard.
- `scripts/schema.ts` — zod for `Dish` / `MenuDay`, checked before anything is saved; the app imports the types.
- `supabase/migrations/` — tables + RLS (anon SELECT only). `sites` (`kind` college | university) → `venues` (`url` = the venue's own page) → `service_slots` (meals: breakfast, brunch, lunch, dinner, formal, snacks = café, bar) and `formals` (booking, dress, guests, price notes; one per venue that holds formal hall); `0004` seeded the University venues once, `0009` reviewed the whole list, `0014` checked the University ones against catering.admin.cam.ac.uk/cafes. Menus: `menu_days` (one per venue/date/service, upserted) → `menu_items` (dishes as printed, replaced per day) → `dishes` (one per site + `dish_key(name)`, tracked across weeks); `dish_stats` view; `ingest_runs` (one row per source per run; service role only). Price lists as posted: `venue_prices` (`0008`, `0011`; member and non-member prices, replaced per venue; a line can price a course or the whole meal at some meals, else it's an item sold at them). Writes go through `save_menu()` / `save_prices()` (service role only).
- `src/lib/data.tsx` — `load()`s sites/venues/slots and the next 7 days of menus (`main.tsx` renders once it has, keeping the prerendered HTML up until then); `useMenuDates`/`useMenuOn` fetch a venue's full menu history (past and future) on demand. `src/lib/time/*` — Europe/London clock, Full Term dates, `openStatus()`; `src/lib/filters.ts` — ranking and sections (Open now / Later today / Other days / Hours not published). `src/lib/seo.ts` — per-page descriptions and schema.org data, sitemap, llms.txt.
- `src/pages/*` — the venue is the unit: `/` map-led Explore (MapLibre GL, loaded in the browser; verified venue/building points from `venues.latitude/longitude/location_source`, `0012`/`0013`/`0015`; every place is its own pin, coloured and iconed by type, and opens a venue card, with Results as a secondary accessible view including unmapped venues; filters in the URL: `q`, `type` (hall/cafe/bar; `hall` is labelled Dining), `open`, `access`, `diet`, `date` (within the loaded menu week), `site`; with Dining also `meal`; `view=list` and `place` preserve the view and selection; `src/lib/explore.ts` validates URL state and pins menu matches to the selected date, without previewing tomorrow; Near me requests location only on click and keeps it in memory), `/colleges` and `/university` (alphabetical site directories), `/:slug` site, college or University (its venues, dining → cafés → bars; old `#venue-slug` links redirect), `/:site/:venue` venue (the menu for `?date=` (default today), beside a calendar of every date that has one and a card of what doesn't change with the date: status, hours with today's in full, access, card payments, map and website links; on a phone the card comes first and the calendar opens from the date; `src/lib/prices.ts` puts the posted prices next to the dishes, or in the meal's heading, folds the rest under "Deals and extras", and shows a list with no course prices as a fixed menu on the days it's served), `/coverage` (per category, how many colleges or places have it and which are missing: menus for the loaded week, dining/café/bar prices (a posted price list or priced dishes), hours, access, card payments; `src/lib/coverage.ts`, also behind the footer count and a venue page's note when it has never had a menu), `/about`, `*` 404. ← (`BackButton`) returns to the previous page, else goes up; scroll is kept per history entry (`useScrollMemory`). Every list uses `src/components/VenueCard.tsx`. White on charcoal (`#1e1e1e`), minimal text, icons from reicon.dev (`reicon-react` via `components/Icon.tsx`; venue types in `lib/icons.ts`); free-text DB fields (`notice`, `hours_text`, `access.text`, …) are research notes for editors and aren't shown.

## Menus

Search (`src/lib/search.ts`, indexed once per loaded snapshot) follows Meilisearch/Typesense/Algolia rather than inventing rules. One document per venue and per dish on a day's menu; a dish carries its place's names. Fields, best first: place name (plus "<site> College"), alias, venue type and meals (`dining`/`cafe`/`bar`, `lunch`…), dish name, diet tags and service. Query words match exactly, as English plurals or `SYNONYMS` (spelling variants seen on menus), the last one also as a prefix unless followed by a space; one word written as two or two as one ("stjohns", "dar bar"); stopwords dropped. Typos (Damerau: 1 from 4 letters, 2 from 8, a wrong first letter costs 2) only for a word that matches nothing as typed, so real words never drift ("cake" ≠ "hake"). Words are optional: results are what matches the most of them. Ranking is tie-breaks: typos, worst field, the query naming the whole place or dish, exact words, then open status. Search sees only what the filters leave: dishes on the selected date (today on Home, never silently tomorrow; browsing still previews the next service), at the selected meal, carrying every selected diet tag. Results bypass opening-status groups. Nicknames are data, not code: `sites.aliases` / `venues.aliases` (`0005`, `0006`), edited in the dashboard. `src/lib/search.test.ts` runs judged queries against a real snapshot (`npm run search:snapshot`) plus rules on made-up data; add a failing query there before changing the rules.

No projected menus: only what a source has published is saved, and sources are re-checked often instead (GitHub Actions runs `npm run ingest` at 05:15, 11:15 and 17:15 UTC; needs repo secrets `VITE_SUPABASE_URL` and `SUPABASE_SECRET_KEY`, then rebuilds the site through `CF_PAGES_DEPLOY_HOOK` when that's set). Days already saved are kept; a day the source still lists is replaced with the latest version. Menus are filed under the meal the venue serves that day when the source names one it doesn't but its brunch counterpart is (Corpus posts Saturday's brunch as "Lunch"): `servedService()` in `src/lib/time/openNow.ts`, applied as menus load.

Hand-transcribed venues (see `sources.ts`): open the URL (PDFs: `curl -A "Mozilla/5.0" … | pdftotext -layout - -`; Sway/Canva: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --dump-dom URL`), write a `.txt` outside the repo, `npm run ingest:manual -- file.txt`. Members-only colleges need a collaborator; their photos of noticeboards and price lists go in the same way (menus via `ingest:manual`, prices via `ingest:prices`).

Reference data (hours, access, venues) is edited in the Supabase dashboard until there's an editor UI. Unknown hours ⇒ no slot (UI says "Hours not published", never "closed").

A venue is somewhere you go to eat or drink (`0009`): not common rooms, tea or coffee gatherings, vending machines or overflow seating. A café that becomes a bar in the evening, in the same room, is one venue: `type` is its icon, and its café (`snacks`) and bar hours also list it under Cafés and Bars (`venueTypes()`), in filters, search and coverage. Formal hall is the `formal` meal: a slot on the dining venue whose room it's held in, or, where it has a room of its own (St John's, Christ's, Clare, Jesus, Magdalene, Pembroke and Robinson's Hall or Dining Hall, Newnham's Clough Hall, Queens' Old Hall), a dining venue of its own. It's booked ahead, so it only counts towards "open now" when Formal is the meal picked or it's all the venue holds; a `formals` row (`Venue.formal` in the app) lists a place under Formal even when its days aren't published.

## Deploy

Static `dist/`, every page prerendered: `/jesus/caff` is `jesus/caff.html`, plus `sitemap.xml`, `llms.txt`, `llms-full.txt`, `robots.txt` and `404.html` (no SPA fallback: a missing page is a real 404). Prerendered pages leave out anything that depends on the clock (`snapshot`). Canonical origin `SITE_URL` in `src/lib/site.ts`.

Cloudflare Pages: build `npm run build`, output `dist`, env `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`. Pages are as fresh as the last build: create a deploy hook (Settings → Builds → Deploy hooks) and save it as the repo secret `CF_PAGES_DEPLOY_HOOK` so each ingest run rebuilds. A venue added in the dashboard 404s until the next build.

## Page alignment

`Container` gives the header, main content and footer the same `max-w-7xl` edges. Directories expand into 1/2/3 columns; prose, hours and menu details keep readable inner widths aligned to the left edge.

## Map

Use verified venue or containing-building coordinates, never a college/site centroid or an invented room location. Unmapped venues stay in Results and directories. Location sources are recorded in Supabase; `0012`/`0013` seed points from the University map; `0015` adds college venues whose OpenStreetMap point falls inside a University-map building of that college (the building's centroid is stored), or whose building a college source names. `src/components/VenueMap.tsx` dynamically imports MapLibre GL (SSR-safe, Vite worker bundled locally) and never groups places: one marker each, with places sharing a coordinate set side by side (`sideBySide()` in `src/lib/map.ts`). Pins take their type's colour from the Cambridge palette (Dining Dark Crest, Café Indigo, Bar Dark Cherry; tokens `--type-*` in `index.css`, validated as categorical colours on both basemaps) and its icon; filled means open now; selection is Cambridge Blue on Dark Blue. The type chips above the map carry the same colours as its legend. It uses OpenFreeMap Bright (light) / Fiord (dark) vector tiles with visible attribution. Styles follow both the theme toggle and system appearance without resetting the camera or selection. Optional `VITE_MAP_LIGHT_STYLE_URL` / `VITE_MAP_DARK_STYLE_URL` override each theme; `VITE_MAP_STYLE_URL` overrides both. On mobile the map fills the viewport below the header edge to edge, with search and filters overlaid; desktop keeps the shared page width and a rounded frame. Wheel/trackpad scrolling and mobile pinch act directly on the map, with rotation disabled; `src/lib/mapGestures.ts` handles desktop Safari GestureEvents on the map canvas only. Page gestures outside the map and keyboard browser zoom are untouched. Default view centres on Cambridge; Show all fits matching points. Opening status is live, while menu date stays explicit.
